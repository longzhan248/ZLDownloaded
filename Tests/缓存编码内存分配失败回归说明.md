# 缓存编码内存分配失败回归（2026-11-10）

## 结论与证据边界

旧实现将全部任务编码为一个二进制 plist Data。在 iOS 27.2 模拟器上，受控拒绝 1 MiB 及以上的 malloc/calloc/realloc 后，128 个真实下载任务稳定触发 SIGTRAP：

```text
Foundation/DataStorage.swift:379: Fatal error: unable to allocate memory for length (1053530)
_assertionFailure
__DataStorage.ensureUniqueBufferReference(growingTo:clear:)
Data.InlineSlice.append(contentsOf:)
Data._Representation.append(contentsOf:)
_BPlistEncodingFormat.Writer.write
PropertyListEncoder.encode
closure #1 in ZYGDLCache.storeTasks
```

这确认了与 Bugly 相同的崩溃机制及调用路径。故障注入不证明线上当时一定发生同样的分配失败，也未证明实际任务规模、内存碎片或其他进程内存占用情况。

## 修复

保留现有任务 Codable 字段与 plist 数组结构，逐任务编码 XML plist 并流式写到同目录临时文件，完成后 rename 原子替换。每个任务完成即释放编码临时对象，不再分配与全部任务输出体积相当的单个 Data。XML 与二进制 plist 均由原 PropertyListDecoder 读取，无需清空缓存，不丢弃恢复数据。

单个异常巨大任务仍可能需要大内存；这次修复消除全量集合输出聚合，不承诺解决任何形式的内存不足。XML 可能增加缓存文件大小和写入成本。读取仍使用现有全量解码路径。

## 运行方法

需要 Xcode iOS 27.2 SDK、已启动的 arm64 iOS 27.2 模拟器，以及真实 ZIPFoundation 源码目录。测试不修改业务工程，不自动启动模拟器，不需要 pod install。

```sh
python3 Tests/run_cache_allocation_regression.py --zip-source '<ZIPFoundation/Sources/ZIPFoundation>' --simulator '<已启动模拟器 UUID>' --optimized --baseline
python3 Tests/run_cache_allocation_regression.py --zip-source '<ZIPFoundation/Sources/ZIPFoundation>' --simulator '<已启动模拟器 UUID>' --optimized
```

第一条使用 HEAD 旧缓存源码，预期子进程 SIGTRAP、退出码 133，脚本非零退出。第二条使用当前源码，预期正常退出并输出三个 PASS。分配故障只注入独立测试子进程，不影响宿主 App。

## 已完成验证

- 旧实现：Debug 与优化构建均在故障注入下触发目标 Data 扩容断言。
- 修复后：Debug 与优化构建均可在相同分配限制下保存、恢复 128 个任务；最终优化样本输出 8,494,219 字节。
- 验证旧二进制缓存读取、XML 特殊字符及中文往返、空数组。
- 人为令某个任务编码抛错：旧缓存字节保持不变，临时文件清理。
- 真实核心源码压力入口：200 次编码解码，4 个线程共 2,000 次状态更新，恢复 128 个任务。
- 本地 Range/慢速/断连 HTTP 服务，24 个真实 URLSession 下载任务交错暂停恢复；保存恢复 24 个任务，其中 9 个包含系统生成的 resumeData。
- 修复后重复上述压力和网络流程，Thread Sanitizer 无报告，进程退出码 0。
- 编译保留了库中已有弃用警告，未构建完整 Oxygen App，未进行真机验收。

修改仅落在下载库源码仓库。主工程 Pods、Podfile.lock、依赖版本及远端均未变更，尚未接入业务 App 或发布。

不能承诺性能完全不受影响。逐任务 XML 会重复结构、失去跨任务二进制去重，元数据场景文件约增至 2.2～2.4 倍；大负载场景读取可能变慢。保存继续在原后台 IO 队列，未将编码搬到主线程；但 `retrieveAllTasks` 保持同步读取，若 manager 在主线程初始化，大缓存读取仍可能影响帧耗时。未进行真机帧率、启动耗时或低端设备验收，模拟器单轮小样本不应解释为线上性能保证。

兼容性限于数据格式与当前解码契约：旧二进制和新 XML 都是标准 plist，字段未变。已经验证旧二进制读取、新 XML 往返；没有运行历史版本 App 二进制进行降级验收，也没有在旧 iOS 真机上验证。
